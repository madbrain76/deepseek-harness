# Agent Note：显式绑定 Web 的所有接口

Status: implemented

[English](2026-09-10-web-all-interfaces-bind.md) | 中文

## 问题

当服务器绑定 `0.0.0.0` 时，Web 运行时已经会派生 LAN 地址信任项并打印可访问的 LAN URL，但命令行提供方会在运行时激活前拒绝这个显式主机地址。这使已记录的 LAN 路径无法使用，也迫使运维方采用未受跟踪的代理规避方案。

## 决策

像其他绑定地址一样接受显式的 `--host 0.0.0.0`。既有运行时会采样非 loopback IPv4 地址，并将其加入浏览器 Host/Origin 信任边界；`--trusted-host` 仍用于授权 DNS authority。默认绑定仍是 `127.0.0.1`，所以远程暴露仍需运维方主动选择。

## 考虑过的替代方案

**要求使用反向代理或端口转发。** 拒绝，因为它会绕过运行时的 LAN 地址发现，不会生成规范的 LAN URL，还会把同样的暴露转移到 Harness 无法验证或解释的配置中。

**更改默认绑定。** 拒绝，因为 LAN 暴露必须保持显式选择。既有调用仍使用 loopback。

## 后果

可信网络中的部署可以直接在 LAN 上提供带认证的 Web UI。由于该 UI 控制具备 shell 与代码执行工具的 agent，包文档现在明确说明：绑定所有接口会向每个可达、能够尝试完成 token 认证浏览器握手的客户端暴露此能力。
